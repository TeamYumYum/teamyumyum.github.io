> 작성자 확인 전 초안이에요. 수치는 학습 기록(`result.json`) 기준이에요. 공개 전에 작성자가 내용을 검토해 주세요.

꾸기의 사진 식사 기록은 지금 Claude Vision이 맡고 있어요. 그 옆에서 우리 모델이 얼마나 할 수 있는지 보려고 음식 이름 분류기를 처음 학습했어요.

## 무엇을 학습했나

| 항목 | 값 |
| --- | --- |
| 데이터 | AI Hub 74번 음식분류 VAL 이미지에서 만든 79,990장, 400종 |
| 모델 | ImageNet 사전학습 ConvNeXt-Tiny, 입력 384px |
| 학습 | 12 epoch, AdamW, 워밍업 + 코사인, 라벨 스무딩 0.1, 첫 epoch는 분류 헤드만 |
| 산출물 | ONNX(opset 17), 클래스별 영양 정보, 서빙 전처리 값 |

해상도와 모델은 50종 부분집합으로 먼저 비교해 정했어요. ConvNeXt-Tiny 384px가 test top-1 0.947로 가장 좋았어요.

## 결과

| 평가 | top-1 | top-5 |
| --- | --- | --- |
| test, 라벨 상자로 자른 사진 | 0.843 | 0.944 |
| test, 전체 사진 | 0.844 | 0.954 |
| 같은 설정으로 다시 학습 | 같은 값 | 같은 값 |

같은 설정으로 다시 학습해도 같은 값이 나와서, 이 숫자를 기준선으로 써도 된다고 판단했어요.

## 그런데 실제 사진에서는

v1 서비스 때 모아 둔 실제 사용자 사진 31장으로 같은 채점기를 돌렸더니, 음식명 F1이 **0.25**였어요. 같은 사진에서 Claude Vision은 0.773이었어요.

원인을 보니 모델이 틀렸다기보다 **문제가 달랐어요.**

- 31장 가운데 정답 음식이 400종 안에 있는 사진은 4장뿐이었어요. 그 4장 중 3장은 맞혔어요.
- 나머지 27장은 400종 밖의 음식이었어요. 분류기는 "모른다"고 답할 수 없어서, 가장 비슷한 400종 이름을 그럴듯하게 내놓았어요.
- 식판처럼 한 사진에 음식이 여러 개 있는 경우도 있었어요. 단일 라벨 분류기는 한 장에 한 음식만 답해요.

## 다음에 할 일

1. **모르는 음식 걸러내기**: 확률을 보정한 뒤 임계값을 정하고, 400종 밖의 메뉴로 거부율을 측정해요.
2. **여러 음식 다루기**: 음식 위치를 찾는 검출기를 분류기 앞에 두는 2단계 구조를 기준선과 비교해요.
3. **평가셋 넓히기**: 여러 음식이 담긴 사진을 따로 모아 단품 사진과 나눠서 채점해요.

정확도 숫자 하나보다 "어떤 사진에서 잰 숫자인가"가 더 중요하다는 걸 배운 첫 학습이었어요.
